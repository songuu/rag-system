# 测试集生成引用错位：修复与实际验证

2026-10-27，使用 `http://localhost:3000/rag-evaluation/datasets`，选择用户截图中的 `重构契丹早期史.epub`，连续生成三轮，每轮 5 题，均成功。没有模拟接口、替换模型响应或修改文档启停状态。

## 已确认的问题与修复

原错误直接来自模型 `sourceIndex` 的范围校验。旧模型 schema 固定允许 0～47，而单篇长文最多只取 6 个分块；传入模型的资料没有显式编号。编号错位时，即便逐字引文实际存在，也会整批失败。

修复后：

- 每批资料显式携带从 0 开始的编号，输出 schema 只允许本批实际编号，生成题数也与请求严格一致。
- 多份资料按片段分批生成，批内校验通过再恢复为全局编号，最终仍绑定服务端读取的真实 chunk ID、文档版本与原文区间。
- 模型给错编号时，只有逐字引文能唯一对应一份已提供资料，才恢复实际来源；多个匹配或虚构引文仍拒绝，不猜测身份、不伪造区间。
- 每批最多一次带校验反馈的修正，跨批去重，不在外层重复回放已经完成的批次；取消信号和原有 120 秒总时限保留。
- 对 Ollama 真正传入 `numPredict` 输出预算，同时限制每题答案、要点及引文规模。通用 `maxTokens` 原本没有在 Ollama 构造路径中转换为对应选项。

实测过程中还捕获了重复题目与超时，最终版本同时处理了这两类生成可靠性问题。短模型探测约 0.4 秒，未以延长总超时替代输出控制。
